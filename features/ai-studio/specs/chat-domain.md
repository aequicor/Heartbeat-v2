# AI Studio. Домен чата

Чат хранит локальную ленту реплик и принадлежит сессии студии. Сессия студии
определяет проект, заголовок и состояние чата в списке. Разговор движка хранит
контекст, необходимый для следующего сообщения. Чат связывается с ним по
сохранённому ключу разговора и подтверждённой конфигурации движка, модели и уровня
рассуждения. Лента остаётся доступна после перезапуска Heartbeat и при недоступном
движке. После редактирования или форка продолжение требует подготовки контекста
по видимым редакциям. [Схема хранения и транзакции](chat-history.md)

## Сценарии

| ID | Правило | Проверка и источник |
| --- | --- | --- |
| HB-CHAT-001 | Когда пользователь подтверждает создание, `ChatCreationDraft` создаёт чат с выбранной конфигурацией и ID подготовленного разговора. Отмена оставляет прежний выбор по умолчанию. | Создать и отменить черновики, затем открыть новый чат. [Создание чата](chat-history.md#создание-чата-и-первая-отправка) |
| HB-CHAT-002 | Когда пользователь отправляет сообщение, `ChatTurnInteractor` резервирует один ход на чат. `SendChatMessageUseCase` сохраняет пользовательскую реплику перед обращением к движку. Если сбой произошёл до передачи запроса, пользователь может повторить отправку той же реплики. | Отправить два запроса одновременно в одном чате и проверить число вызовов движка. Затем воспроизвести отказ до передачи и проверить, что ручной повтор сохраняет ключ и позицию реплики. [Отправка сообщения](chat-history.md#отправка-сообщения-с-вложением) |
| HB-CHAT-003 | Пока движок выполняет ход, очередные фрагменты дополняют одну реплику ассистента. После завершения, остановки или ошибки сценарий сохраняет полученный текст, рассуждения и итоговый статус. При неопределённом результате студия сверяет состояние с движком, если соединение позволяет. Автоматический повтор отправки запрещён. | Получить текст и рассуждения, прервать ход и открыть историю снова. [Потоковый ответ](chat-history.md#потоковый-ответ-инструменты-и-завершение) |
| HB-CHAT-004 | Когда пользователь открывает чат, `ChatHistoryInteractor` читает локальную историю. Перед отправкой `PrepareChatContextUseCase` открывает сохранённый разговор. После редактирования или форка сценарий подготавливает контекст из видимых редакций. Если контекст недоступен, чат сохраняет историю и сообщает причину отказа в отправке. | Перезапустить студию, открыть тот же чат и продолжить разговор. Отдельно проверить недоступный движок, форк и правку. [Продолжение разговора](chat-history.md#чтение-истории-и-продолжение-разговора) |
| HB-CHAT-005 | Когда пользователь применяет выбор, `ApplyChatConfigurationUseCase` проверяет совместимость всей комбинации. При смене движка сценарий подготавливает разговор с контекстом чата до фиксации конфигурации. Если подготовка или применение завершается ошибкой, чат сохраняет прежнюю конфигурацию. | Пройти три шага визарда, проверить шапку до и после применения. Повторить с несовместимым выбором и недоступным контекстом. [Визард смены движка](../../../design/specs/engine-change-wizard.md) |

## Use case и интеракторы

| Компонент | Вход и результат | Ответственность |
| --- | --- | --- |
| `SessionBootstrapInteractor`, `ChatCreationDraft` | Проект для нового чата или ID существующей сессии студии, затем выбор движка, модели и уровня рассуждений. | Интерактор открывает черновик конфигурации. При первой отправке из нового чата черновик сохраняет студийную сессию и ID подготовленного разговора. Для существующего чата подтверждение передаёт выбранную комбинацию в `ChatTurnInteractor`. |
| `ChatTurnInteractor` | ID сессии студии и команда отправки, остановки, ответа на запрос разрешения или применения настроек. | Пока в чате идёт отправка или применение настроек, интерактор удерживает один слот этого чата. Остановка и ответ на запрос разрешения относятся к открытому ходу. Для другого чата действует отдельный слот. |
| `SendChatMessageUseCase` | ID сессии студии, текст и вложения. Во время хода публикует снимки `ChatTurn`. | Сохраняет пользовательскую реплику перед передачей движку. Фрагменты обновляют одну реплику ассистента. При остановке или сбое сохраняет полученную часть и итоговый статус. |
| `PrepareChatContextUseCase` | ID сессии студии. Возвращает разговор движка, готовый к отправке. | Читает сохранённый ID разговора, проверяет актуальность контекста, восстанавливает разговор в рабочем каталоге чата и применяет сохранённые модель и уровень рассуждений. При отказе подготовка заканчивается до передачи сообщения. |
| `ApplyChatConfigurationUseCase` | ID сессии студии и полная выбранная комбинация. Возвращает результат применения. | Применяет настройки в сохранённом разговоре и записывает их, если конфигурация чата с момента чтения осталась прежней. При ошибке пытается откатить настройки движка и запрашивает закрытие разговора, если откат не удался. В текущей реализации перенос контекста в другой движок недоступен. |
| `ChatHistoryInteractor` | ID сессии студии или ID сохранённой части. Для правки и форка получает ID чата и редакции. | Читает историю, вложения и полное содержимое частей из локального хранилища. Правка и форк изменяют локальную ленту. Для следующей отправки после правки или форка требуется подготовить контекст движка. |

## Поток данных

Compose отображает состояние чата и передаёт действия в `presentation.chat`.
Визард отображает состояние `ChatCreationDraft` и передаёт ему выбор параметров,
подтверждение и отмену. Для запроса моделей актуален результат последней попытки
в открытом визарде. Шапка показывает последнюю сохранённую конфигурацию. [Визард смены движка](../../../design/specs/engine-change-wizard.md)

Store передаёт отправку в `ChatTurnInteractor`, а открытие истории — в
`ChatHistoryInteractor`. Ход охватывает одну пользовательскую реплику и
связанный ответ движка. Он завершается ответом, остановкой или ошибкой.
Домен через `DataSource` читает и сохраняет чат, открывает разговор и получает
события хода. Реализации источников данных переводят записи SQLite и события
движка в доменные модели.

Desktop предусматривает повторную доставку исходной пользовательской реплики после подтверждённой недоставки. Действие «Продолжить» дописывает ответ в прежнюю карточку. Для него транспорт должен связать продолжение с начатым ходом. При HTTP 429 интерфейс также учитывает срок ожидания, если сервер его сообщил. Штатный DSH ACP возобновляет разговор для следующего сообщения. [Рабочая область агента Desktop](../../../design/specs/desktop-aurora-agent-workspace.md#ошибки-повтор-и-продолжение)

Когда DSH передаёт через ACP код HTTP 429, студия показывает «Слишком много запросов» в ответе агента и сохраняет эту причину вместе с полученным содержимым. В проверенном профиле DSH с Pi-AI срок из `Retry-After` через ACP в студию не поступает.
