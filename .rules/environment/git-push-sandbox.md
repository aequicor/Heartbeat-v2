# Git push из песочницы DSH

## Применимость

Отправка ветки в GitHub (`git push`) из DeepSeek Harness на Windows при активной файловой
песочнице (`workspace-write`).

## Условие

`git push` завершается с ошибкой `sh.exe ... couldn't create signal pipe, Win32 error 5`,
затем `could not read Username for 'https://github.com'`. Песочница блокирует создание
именованных каналов, поэтому Git не может запустить механизм запроса учётных данных
(Git Credential Manager).

## Требуемое поведение

Повтори ровно ту же команду `git push` один раз с расширенным доступом
(`sandbox_permissions: danger-full-access`) и обоснованием для оператора: Git запустит штатное
окно входа GitHub, файлы в репозитории команда не меняет. Не меняй URL пульта и не передавай
учётные данные в команде.

## Исключения

Если сетевая команда Git завершилась в песочнице успешно (учётные данные уже кэшированы),
расширенный доступ не нужен. Локальные команды Git работают в песочнице как обычно.
