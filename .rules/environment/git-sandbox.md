# Git из песочницы DSH

## Применимость

Git в DeepSeek Harness на Windows при активной файловой песочнице (`workspace-write`), когда
команде нужен вспомогательный процесс msys2: запрос учётных данных при `git push` или подпись
коммита через `ssh-keygen`.

## Условие

`git push` завершается с ошибкой `sh.exe ... couldn't create signal pipe, Win32 error 5`, затем
`could not read Username for 'https://github.com'`. Подписанный коммит (`commit.gpgsign=true`,
`gpg.format=ssh`) завершается с `ssh-keygen ... NtCreateDirectoryObject ... 0xC0000022` и
`fatal: failed to write commit object`.

Песочница блокирует именованные объекты и каналы, поэтому Git не может запустить вспомогательный
процесс.

## Требуемое поведение

Повтори ровно ту же команду один раз с расширенным доступом
(`sandbox_permissions: danger-full-access`) и обоснованием для оператора: Git запустит штатное
окно входа GitHub или подпишет коммит ключом SSH, файлы в репозитории команда не меняет. Не меняй
URL пульта, не отключай подпись и не передавай учётные данные в команде.

## Исключения

Если команда завершилась в песочнице успешно (учётные данные уже кэшированы, подпись не
требуется), расширенный доступ не нужен. Операции Git без вспомогательных процессов работают в
песочнице как обычно.
