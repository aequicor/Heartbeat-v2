# Композиция SQLDelight-схем в Heartbeat

## Условия применимости

Gradle-модуль Heartbeat с плагином `heartbeat-sqldelight`, особенно агрегатор
`storage/database` и модули фич с файлами `.sq`.

## Наблюдаемое поведение

1. Файл `.sq` должен лежать в каталоге, совпадающем с `packageName`:
   `src/commonMain/sqldelight/<package path>/<Name>.sq`. Файл в корне `sqldelight/`
   отклоняется сообщением `SqlDelight files must be placed in a package directory`.
2. Агрегатор без собственного `.sq` не генерирует `HeartbeatDatabase`, даже если
   объявлены `dependency(project(...))`. Достаточно `.sq` с комментарием, чтобы
   композиция зависимых схем выполнилась.
3. Сгенерированный агрегат расширяет сгенерированные интерфейсы зависимых модулей
   (`HeartbeatDatabase0`, `HeartbeatDatabase1`, ...) и ссылается на их query-классы.
   Поэтому зависимые модули должны быть и обычными compile-зависимостями агрегатора,
   а не только аргументами `dependency(...)`.
4. Для `dependency(project(...))` имя базы во всех модулях должно совпадать
   (`HeartbeatDatabase`); различаться должен только `packageName`.

## Требуемое поведение

Держи `.sq` в package-каталоге, добавляй в агрегатор маркерный `.sq` и явные
`implementation(project(...))` для каждого модуля схемы. Новый модуль схемы
подключай одновременно в `dependency(project(...))` и в `commonMain`-зависимости
`storage/database`.

## Исключения

Модули фич без собственной схемы не подключаются к агрегатору. Миграции `.sqm`
остаются только в агрегаторе и не дублируются в модулях схем.
