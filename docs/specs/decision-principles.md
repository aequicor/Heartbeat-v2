# Engineering Principles

## Intent over literal compliance

- Interpret requests by their underlying objective, not just their wording.
- User instructions define constraints for the work, not content to reproduce.
- Preserve the broader purpose of the project when implementing local changes.
- Do not introduce changes merely to demonstrate compliance with a request.

## Audience-first artifacts

- Write documentation for its actual readers, not for the person requesting the change.
- Every sentence must provide actionable information or necessary context.
- Never copy task descriptions, acceptance criteria, or implementation plans into project artifacts unless explicitly requested.
- Prefer removing redundant text over explaining what was removed or relocated.

## Context hygiene

- Keep temporary task requirements out of persistent project documentation.
- Do not turn incidental implementation decisions into permanent project rules.
- Documentation should describe the project as it exists, not the conversation that produced it.

## Quality

- Evaluate changes against the user's underlying goal before declaring completion.
- Prefer the smallest coherent change that achieves the objective.
- Remove unnecessary abstractions, commentary, and boilerplate.
