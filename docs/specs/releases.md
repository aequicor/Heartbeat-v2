# Каналы выпуска

| Канал | Запуск | Результат |
| --- | --- | --- |
| `alpha` | Изменение в `master` затрагивает сборку бандлов | Автоматическая публикация затронутых desktop-бандлов без оптимизации и обфускации |
| `beta` | Ежедневно в 01:00 по `Europe/Samara` | Один конвейер публикует оптимизированные и обфусцированные desktop-бандлы и самостоятельные сборки Android и iOS |
| `release` | Владелец вручную запускает выпуск после проверки функциональности и выбора feature flags | Стабильные артефакты с проверенной функциональностью. Desktop-релиз включает публикацию платформы. |

`Europe/Samara` — часовой пояс ночного запуска. Эта страница задаёт целевое поведение конвейеров.

## Требования и проверка

| ID | Требование | Источник | Критерий проверки |
| --- | --- | --- | --- |
| HB-REL-001 | Когда изменение в `master` затрагивает сборку desktop-бандлов, конвейер `alpha` должен собрать и автоматически опубликовать затронутые бандлы без оптимизации и обфускации. | Процесс alpha из постановки проекта | Проверить запуск после изменения бандла, параметры сборки и опубликованные артефакты. |
| HB-REL-002 | В 01:00 по `Europe/Samara` конвейер `beta` должен запустить единый ночной выпуск desktop-бандлов и сборок Android и iOS. Перед публикацией конвейер должен выполнить применимую для каждого формата оптимизацию и обфускацию. | Процесс beta из постановки проекта | Проверить расписание, состав артефактов и параметры обработки каждой сборки. |
| HB-REL-003 | Когда владелец запускает `release` после проверки функциональности, конвейер должен выпустить стабильные артефакты с утверждёнными feature flags. Для desktop конвейер должен опубликовать платформу. | Процесс release из постановки проекта | Проверить ручной триггер, список включённых flags и наличие desktop-платформы в выпуске. |
